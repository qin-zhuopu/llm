# 商业垂直领域大模型市场报告 — 编制提纲

> 本文档是市场报告（`docs/vertical-llm-market-report.md`）的编制说明与大纲，
> 用于明确：**为什么写、写什么、数据从哪来、数据缺陷、如何完善、报告结构**。
> 编制日期：2026-08-26

---

## 一、为什么写这个报告（目的）

1. **把结构化数据变成可读的市场洞察**
   本仓库积累了 110 个垂类模型 + 3 个平台的结构化数据（`domains/`），单看 YAML 无法形成判断。报告的价值是把离散数据聚合成"领域格局、公司形态、护城河、商业模式"的整体判断。

2. **用实证数据验证/修正行业共识**
   市场上关于"垂类 AI 是否有护城河""模型是否是壁垒"有大量定性讨论。本报告用数据集的三维度评分、benchmark 来源分布等**硬数据**来支撑或修正这些判断，而非人云亦云。

3. **暴露行业的数据可信度真相**
   本数据集能量化一个通常被忽视的事实：**91.5% 的性能数据是公司自报**。这是报告要传递的核心警示——垂类 AI 的"性能领先"绝大多数未经独立验证。

4. **服务决策**
   为投资、采购、竞品分析、技术选型提供一个有据可查、可回溯（每条数据有 `data/raw/` 原始证据）的参考。

## 二、写哪些方面（内容范围）

| 维度 | 具体内容 |
|------|---------|
| **领域格局** | 22 个领域的模型分布、成熟度分级（哪些领域密集/稀疏、最高分领域） |
| **公司形态** | 模型原生型 / 模型系统型 / 工作流应用型三分类及代表 |
| **护城河分析** | 各领域壁垒来源（专有数据 / 工作流 / 分发 / 结果反馈闭环） |
| **商业模式** | 席位订阅 / 企业年合同 / 按结果计费 / 里程碑版税 |
| **数据可信度** | benchmark 来源分布（自报/论文/第三方/排行榜），可信度警示 |
| **战略判断** | 哪些领域最可能形成模型级壁垒；技术领先 vs 商业领先的分离 |

**不写**：具体投资建议、财务预测、未审计数据的背书。

## 三、数据从哪里来（数据来源）

### 一手数据源
- **`domains/**/*.yaml`**：110 个模型的结构化数据（name/company/domain/parameters/training/benchmarks/tech_stack 等）
- **`platforms/*.yaml`**：3 个 AI 平台
- **`data/raw/{slug}/`**：每个模型的原始抓取资料 + `sources.json`（含 URL、抓取日期、来源类型），保证每条数据可回溯

### 分析工具（脚本产出的聚合素材）
- **`scripts/check.py`**：三维度质量评分（业务 B / 技术 T / 来源 S），用于质量门槛筛选
- **`scripts/build_kg.py`**：知识图谱（公司-模型-领域-标签关系），用于关系分析
- **benchmark `source` 字段**：用于可信度分布统计

### 数据采集方法论
- 详见 `AGENTS.md`（7 阶段流水线）和 `docs/search-methods.md`（搜索渠道）
- 核心原则：跟着"融资/官网/风投报告"走，而非模型 API 目录

### 质量门槛
- 报告仅纳入 `check.py` 综合分 ≥ 70 的模型（当前 90/110），排除 20 个低质量数据

## 四、当前数据的缺陷

> 基于 `docs/data-quality-review.md` 复盘结论，诚实列出局限。

| # | 缺陷 | 影响 | 严重度 |
|---|------|------|:---:|
| 1 | **91.5% benchmark 为公司自报**（314/343），仅 5% 有论文、1.2% 第三方 | 性能对比可信度低，报告结论需加"自报口径"限定 | 🔴 高 |
| 2 | **48% 模型仅单一来源**（53/110 只有 1 个 source，34 个有 3+ 个） | 来源维度(S)偏低（均分 64），交叉验证不足 | 🟡 中 |
| 3 | **领域分布不均** | 金融/法律/医疗密集（10+），政务/软件开发仅 1 个，稀疏领域样本不足以下结论 | 🟡 中 |
| 4 | **偏向可公开搜索的公司** | 纯内部模型（大厂未公开的）系统性缺失，样本有幸存者偏差 | 🟡 中 |
| 5 | **数据快照性** | 融资/估值/客户数变化快，快照于 2026-08，部分数据会过时 | 🟢 低（有 check_freshness.py 跟踪） |
| 6 | **缺结构化商业字段** | 融资额/ARR/客户数散在 description 文本里，未结构化，难做定量商业分析 | 🟡 中 |

## 五、如何进一步完善数据

按优先级排列：

### P1 — 提升来源多样性（对应缺陷 2、1）
- 对 53 个单一来源模型，补抓论文/新闻/第三方来源，目标每个模型 ≥ 2 个独立来源
- 优先补有论文的模型的 arXiv 来源，提升 paper 类 benchmark 占比
- 工具：`scripts/backfill_raw.py`（已支持从 MD 提取 URL 批量抓取）

### P2 — 补充结构化商业字段（对应缺陷 6）
- 考虑在 schema 增加可选字段：`funding`（融资额/轮次）、`valuation`、`arr`、`customers`（客户数）
- 从现有 MD/raw 中提取，使商业维度可定量分析
- 需评估 schema 改动成本

### P3 — 平衡领域覆盖（对应缺陷 3）
- 针对稀疏领域（政务、软件开发、能源、客服）主动搜索补充
- 目标每个领域至少 3-5 个高质量模型

### P4 — 扩大样本、减少幸存者偏差（对应缺陷 4）
- 系统爬取风投年度报告（Menlo/Bessemer/a16z）提取更多公司
- 关注大厂内部模型的公开信号（财报、技术博客）

### P5 — 数据新鲜度维护（对应缺陷 5）
- 定期 `check_freshness.py --stale` 识别过期数据
- 对 stale/expired 模型用 `backfill_raw.py --force` 刷新
