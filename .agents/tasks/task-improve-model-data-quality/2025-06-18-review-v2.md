# Schema v2 with metadata restoration and garbage file pruning

This second pass reviews the cumulative diff after fixes for all 7 issues raised in the v1 review. The branch redesigns model.schema.json toward training-centric fields, deletes 11 model entries with useless scraped markdown, regenerates 65 YAML files with richer descriptions, and applies a batch metadata restoration (release_date, website, tags, access, region) via `restore_metadata.py`. Hallucinated 2026 dates are fixed, Med-PaLM 2 data is fully restored with benchmarks and arxiv reference, and the broken relative URL is gone. Watch for: new schema fields (training, tech_stack, benchmarks, datasets) remain unpopulated in 61 of 65 files (confirmed); 4 files have field-ordering problems where metadata appears after `references` (confirmed); 2 reference URLs use LinkedIn shortlinks (`lnkd.in`) that will rot quickly (confirmed).

**Verdict**: APPROVED

## High-level view

The metadata regression — the most critical v1 issue — is fully resolved. All 65 surviving files now carry `release_date`, `website`, `tags`, `access`, and `region`.

The 11 deleted model entries all had MD source files containing only navigation fragments or login page text. Two of these (Khanmigo, Insilico Medicine) had moderately useful structured YAML on main, but the deletion rationale (garbage source data, MD-driven pipeline) is defensible.

The schema's aspirational fields (`training`, `tech_stack`, `benchmarks`, `datasets`) are populated in only 2-4 of 65 files. HuatuoGPT is the single exemplar where the new schema delivers real value. Populating the remaining files would require manual research beyond what the scraped MD provides.

Field ordering and list-indent style are inconsistent: 4 files place metadata fields below `references`, and indentation style varies between `restore_metadata.py`-processed files and LLM-generated ones.

## Deleted entries: borderline cases

Of the 11 deleted pairs, 9 are unambiguously justified (MD content is login redirects, navigation menus, or unrelated marketing). Two warrant mention:

Khanmigo's main-branch YAML had a specific description ("与OpenAI合作开发的自适应辅导AI，采用苏格拉底式教学法"), three capabilities, and correct metadata. Insilico Medicine documented clinical-stage AI drug discovery with Phase I-III pipeline claims. Both had garbage MD but functional YAML that represented real product knowledge. Deleting them loses curated data that can't be recovered from the MD source.

## Unverified access-type drift

The `restore_metadata.py` script only restores *missing* fields — it doesn't overwrite existing values. This means several LLM-regenerated `access` values that differ from main persist without verification: Palantir AIP changed from `private-deployment` to `saas`, SF Tech from `internal-only` to `api`. These may be correct (both companies have expanded access models) but were generated by the LLM from marketing material, not confirmed against product documentation.

## YAML formatting root cause

The 4 files with out-of-order fields (`jasper-ai`, `haomo-drivegpt`, `fourkites-ai`, `shopify-sidekick`) were regenerated by the LLM with metadata fields already present — so `restore_metadata.py` skipped them entirely and never applied its ordered-write logic. A normalization pass over all files (not just those needing field restoration) would fix this.
